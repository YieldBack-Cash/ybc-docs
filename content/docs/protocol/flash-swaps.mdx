The AMM holds only PT and V. YT is created and destroyed on the fly, inside a
single transaction, by pairing a PT flash swap with a yield-manager mint or burn.

## Buying YT

`Router::swap_v_for_yt` → `AMM::flash_swap_pt(receiver = YieldManager, …)`

```
1. AMM advances v_from_pool vault shares to the YM
   (its payment for the PT it is about to buy)

2. AMM calls YM.on_flash_receive_pt(
       yt_out, v_from_pool, user, max_v_in, vault_rate, amm)
   — vault_rate is the rate the AMM already read to price this trade

3. YM pulls max_v_in from the user, computes
       v_to_mint  = yt_out * 1e7 / rate
       user_cost  = v_to_mint - v_from_pool     ← the YT price
   and refunds the excess

4. YM mints yt_out PT (to itself) + yt_out YT (to the user)

5. YM transfers the yt_out PT to the AMM as repayment,
   and asserts it leaked no PT
```

Net effect: the user pays only the YT price, bounded by `max_v_in`. The pool's V
advance covers the rest of the mint and is repaid in PT.

## Selling YT

`Router::swap_yt_for_v` → `AMM::flash_swap_v(receiver = YieldManager, …)`

```
1. Router first transfers the user's yt_in YT to the YM, so the user's signed
   auth entry is a fixed-argument transfer rather than one that depends on
   pool state

2. AMM lends pt_borrowed = yt_in PT to the YM

3. AMM calls YM.on_flash_receive_v(
       pt_borrowed, v_owed, user, min_v_out, vault_rate, amm)

4. YM burns the pair (pt_borrowed PT + yt_in YT)
       shares_returned = pt_borrowed * 1e7 / rate

5. YM repays v_owed vault shares to the AMM and sends the remainder
   (at least min_v_out) to the user
```

## Callback safety

Only the registered pool can drive either callback, and every
movement of user value inside a callback is independently authenticated against
`user`.

The flash entrypoints themselves are *not* restricted to the router — anyone may
call `flash_swap_pt` / `flash_swap_v`. Three things make that safe:

| Guard | Effect |
|-------|--------|
| The AMM asserts `receiver` equals the registered yield manager | A flash swap cannot deliver funds anywhere else. |
| The YM callbacks call `get_pool().require_auth()` | Only the real pool is the direct invoker during a genuine flash swap; a caller impersonating it fails. |
| Each user-fund movement inside the callback is separately `require_auth`'d against `user` | A direct caller naming a victim as `user` cannot pull that victim's V or YT. |

`set_pool` is **one-shot**, set by the factory at deploy time to the pool it just
created, so the trusted pool can never be swapped out.

## The rate hint

The exchange rate is passed as an explicit argument into every PT/YT call inside
a callback, so those contracts never call back into the yield manager for it.
That would be re-entry while the yield manager is on the stack, which the Soroban
host rejects. The hint keeps the flow single-pass.

The same figure comes back on the callback itself, where it divides `v_to_mint`.
That is safe because the pool sources it from `get_exchange_rate` and so cannot
supply anything except the value already in storage — re-applying it is a no-op.

Pairing holds by construction: `create_market` threads one `vault` value into
both contracts, and `set_pool` is one-shot.

<Callout type="warn">
The AMM and yield manager share the flash-callback ABI and are versioned as a
**pair**. Installing one without the other yields markets whose flash swaps fail
at the callback.
</Callout>
